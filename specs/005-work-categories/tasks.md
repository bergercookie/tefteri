# Tasks: Work Categories and Statistics

**Input**: Design documents in `/specs/005-work-categories/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/api.md, quickstart.md. Features 003 (labels, label history, orphan mark) and 004 (weekly commitment, milestones) are implemented and are dependencies. Feature 006 is implemented before this one, so migration `0021` follows `0020`.

**Tests**: Required (constitution V). Tests come first inside each phase and must fail before the code that satisfies them.

**Organization**: Phases are the milestones M1 to M6 of plan.md. Inside a phase every task carries the user story it serves. Each phase ends with a completion-criteria task that must pass before the next phase starts.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (other files, no dependency on an unfinished task)
- **[US#]**: user story of spec.md: US1 every completed task in one of three categories, US2 the same numbers for a month and a year, US3 honest statistics, US4 no cap, US5 unusual projects and moved tasks, US6 maintenance is first-class
- Commands use `source /root/tefteri-env.sh` in this session. On a normal machine use `devbox shell`.
- Paths: `backend/` is the Python project, `frontend/` is the Flutter project.
- The task app name stays out of every file except `backend/src/tefteri/adapters/vikunja/`, the registry, the config, the live test files and the `just` recipe names that already exist.
