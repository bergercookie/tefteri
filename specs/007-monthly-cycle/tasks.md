# Tasks: Monthly Planning and Review

**Input**: Design documents in `/specs/007-monthly-cycle/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/api.md, quickstart.md. Features 003 (labels), 004 (milestones, done date, theme at done, the `FocusProvider` seam) and 006 (key results, series, links) are implemented first. Feature 005 (work category counts) is implemented before this feature (order 004, 006, 005, 007, 008).

**Tests**: Required (constitution V). Tests come first inside each phase and must fail before the code that satisfies them.

**Organization**: Phases are the milestones M1 to M6 of plan.md. Inside a phase every task carries the user story it serves. Each phase ends with a completion-criteria task that must pass before the next phase starts.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (other files, no dependency on an unfinished task)
- **[US#]**: user story of spec.md: US1 pick the themes, US2 targets, US3 key results behind each choice, US4 change the focus mid-month, US5 review targets against results, US6 update key results and see the gap, US7 off-plan trend, US8 decide per theme, US9 immutable snapshot, US10 theme-based Month view
- Commands use `source /root/tefteri-env.sh` in this session. On a normal machine use `devbox shell`.
- Names from features 004, 005 and 006 come from their design files. Task T001 checks them against the merged code first.

## Dependencies and order

- Phase 1 before all others. Phase 2 before Phase 3 (the review reads the focus entries). Phase 3 before Phase 4. Phase 4 before Phase 5 (the client uses the API). Phase 6 last.
- Inside a phase, tasks marked [P] touch different files and can run together. A task without [P] either touches a file that an earlier task also touches, or needs a result of one. Tests are written first and must fail before the code that satisfies them.
- Inside Phase 1: the domain tests before `domain/monthly.py`; the model task before the migration task.
- Inside Phase 3: the review tests before the service tasks; the reader task first, then draft part 1, key results, categories, decisions, and store last.
- User story dependencies: US1 (the focus and the picker) is the base for all. US2 and US3 need US1 (US3 also needs feature 006). US4 needs US1. US5 needs US1. US6, US7 and US8 need US5. US9 needs US5 to US8. US10 needs US1 and shows the review of US9.
- Feature dependencies: 003, 004 and 006 before this feature; 005 before this feature. Feature 008 needs US9.

## Parallel example

The unit test tasks of Phase 1 and the integration test tasks of Phases 2 and 3 each have their own test file and run in parallel. The domain rule tasks share `domain/monthly.py`, so they run in order. In Phase 5 the widget test tasks run in parallel because each has its own test file.

## MVP

US1, US2, US5 and US9 together are the minimum that gives value: a stored focus with targets, a review that counts milestones against them, and a snapshot that never changes. US3, US6 and US8 are P1 and ship in the same feature (the key results behind the choice, the gap, and the decisions that close the cycle). US4, US7 and US10 are P2 on the same base.
