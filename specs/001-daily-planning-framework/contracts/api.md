# REST API Contract (v1)

Base path `/api/v1`. JSON bodies; errors use `{"detail": "...", "code": "..."}`. The
authoritative machine-readable contract is the OpenAPI document generated by the server
(`just backend::openapi` writes it to `docs/openapi.json`), and a test fails if it changes
without the file being updated.

All endpoints except `/auth/*` and `/health` require an authenticated user and only ever
return that user's data. Item list endpoints accept `context=all|work|life` (default `all`).

## Auth
- `POST /auth/login` - username + password → session/token.
- `POST /auth/logout`, `GET /auth/me`.
- `POST /auth/password` `{current_password, new_password}` - change your own password (min 8
  characters); your other sessions end.
- `GET /auth/methods` - which login methods are enabled (v1: `{"password": true}`).

## Users (admin only)
- `GET /users`, `POST /users` `{username, password, is_admin?, timezone?}`, `PATCH /users/{id}`
  `{password?, is_admin?, disabled?, timezone?}` (a new password resets a forgotten one),
  `DELETE /users/{id}` (deletes the user's data). 403 `forbidden` for non-admins; 409
  `username_taken`; 409 `not_allowed` for self-lockout or removing the last administrator.

## Connections and sync
- `GET /connections`, `POST /connections`, `PATCH /connections/{id}`,
  `DELETE /connections/{id}`.
- `GET /connections/{id}/containers`, `PATCH /connections/{id}/containers/{cid}` (context).
- `GET /connections/google/authorize`, `GET /connections/google/callback` - Google OAuth.
- `POST /sync` - sync all connections; `POST /connections/{id}/sync` - one connection.
  Response: per-connection outcome, counts, errors, `conflicts`.
- `GET /sync/status` - last sync time/outcome per connection.
- `GET /conflicts`, `POST /conflicts/{id}/resolve` with `{"resolution": "keep_local|keep_remote"}`.

## Tasks
- `GET /tasks` (filters: `context`, `status`, `from`, `to`, `goal_id`, `unscheduled`).
- `POST /tasks`, `GET /tasks/{id}`, `PATCH /tasks/{id}`, `DELETE /tasks/{id}`,
  `POST /tasks/{id}/complete`.
- `PUT /tasks/{id}/schedule` `{start, end?}` / `DELETE /tasks/{id}/schedule` - writes the
  date/time back to the task backend; creates no calendar event.

## Calendar
- `GET /calendar` (`from`, `to`, `context`) → calendar entries **and** scheduled tasks, each
  tagged `type: entry | task`.
- `POST /calendar/entries`, `PATCH /calendar/entries/{id}`, `DELETE /calendar/entries/{id}`.

## Notes
- `GET /notes` (`kind`, `date`, `context`), `POST /notes`, `GET /notes/{id}`,
  `PATCH /notes/{id}`, `DELETE /notes/{id}`.
- `GET /notes/daily/{date}` - get or create the daily note.
- `POST /notes/daily/{date}/append` `{text, task_id?}` - add text, link to task.
- `POST /tasks/{id}/notes` - link/create a note for a task.

## Planning
- `GET /goals` (`period_type`, `period_start`, `parent_id`), `POST /goals`,
  `PATCH /goals/{id}`, `DELETE /goals/{id}?linked_tasks=keep|delete`.
- `POST /goals/{id}/breakdown` - create child goals/tasks.
- `GET /plans`, `POST /plans`, `GET /plans/{id}`.
- `GET /views/day/{date}`, `/views/week/{date}`, `/views/month/{date}`, `/views/year/{year}`
  - aggregated data for each planning view (entries, tasks, notes, goals, progress).

## Reviews
- `GET /plans/{id}/review` - generate or fetch the planned vs completed summary.
- `PUT /plans/{id}/review/retrospective` `{body}` - saves the retrospective and writes it to
  the notes backend.

## Operations
- `GET /health`, `GET /version` (returns the build version string).
